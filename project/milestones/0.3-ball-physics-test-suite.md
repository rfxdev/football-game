# 0.3 Ball Physics Test Suite

**Status:** Done

A GdUnit4 suite over what [0.2 Sandbox Scene](0.2-sandbox-scene.md) built — the fake-Z ball, and the boundary and goal predicates — from day one. Correctness, not feel — no thresholds on anything still being tuned.

**Notes:**

- **This is the cheapest test coverage the project will ever get, and everything inherits what it fails to catch.** Height is a plain float with no rendering involved, so it tests at close to zero cost, while every system built above it assumes the arithmetic underneath is right. Rationale for what to automate and why in [Automation Testing](../../ways-of-working/automation-testing.md)
- **From day one, not after the first milestone.** Retrofitting it means writing tests against behaviour you've already started trusting
- **Edge tests read `Pitch`'s constants and the mouth they're given, never the frame's numbers.** [3.0 Pitch and Camera](3.0-pitch-and-camera.md) moves the constants to the pitch's lines, and the tests follow without a rewrite
- **Goal or out is decided by order, not by the predicates.** The out predicate holds for a goal's crossing too, so the goal is checked first. The exactly-one test asserts the outcome where that order lives, not the two predicates side by side
- **No Asking, Session shape, Attributes or Sprites.** Scaffolding on the *neither* route, so it exits when the suite passes, per [Exit Criteria](../README.md#exit-criteria) — with no player to read an attribute and nothing new to draw
- **No 360 Testing.** [0.1 Input Map](0.1-input-map.md) is configuration with no tests, and nothing here reads input. 0.2's ball is this milestone's own deliverable, by 0.2's handoff; its sheet and sideload tests gain nothing here and lose no assumption

**Testing:** no sideloaded data — the frame tests read the committed sheet description, per [Local Data](../../docs/decisions/licensing-and-ip.md#local-data).

- Each of [Ball Movement](../../docs/design/match-engine/ball-physics-and-aerial-simulation.md#ball-movement)'s criteria
- Each of [Fake Height](../../docs/design/match-engine/ball-physics-and-aerial-simulation.md#fake-height)'s criteria — gravity, the slowdowns and the cut-off measured from the ball's motion, and no gravity on the tick it's kicked up
- A ball rolled along the ground stops on the tick normal's ground rate gives, stays stopped, and resets the scenario at rest
- A bounce loses and keeps exactly the normal pitch's fractions of ground and vertical speed, per [Pitch Conditions](../../docs/design/match-engine/ball-physics-and-aerial-simulation.md#pitch-conditions). The other six are [7.2 Pitch Conditions](7.2-pitch-conditions.md)'s
- Each of [Showing Height](../../docs/design/match-engine/ball-physics-and-aerial-simulation.md#showing-height)'s criteria — drawn positions, a rolling ball's frame timing, layering
- The ball's frame is a function of its state alone — one still frame when it isn't moving — and drawing never changes that state, per [Sheets](../../docs/design/match-engine/sprites.md#sheets)
- The out predicate at each edge of each line, at every height, per [The Pitch](../../docs/design/match-engine/pitch-and-environment.md#the-pitch)
- The goal predicate — line crossed **and** under the bar — at each edge of the mouth and the bar, and every goal-line crossing exactly one of a goal or out, per [The Goal](../../docs/design/match-engine/pitch-and-environment.md#the-goal)
- Determinism — the same scenario run twice ends in the same state, per [Automation Testing](../../ways-of-working/automation-testing.md#determinism)
- The shared per-tick invariant check starts here, with the ball's: no NaN position, height never below 0, the ball in the frame or the scenario reset

The goal predicate gets corner cases specifically because it is two terms ANDed together, and that is where the bugs live.
