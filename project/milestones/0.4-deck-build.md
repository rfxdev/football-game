# 0.4 Deck Build

**Status:** Ready

One Linux build onto the Steam Deck, purely to prove the pipeline works, starting fullscreen as exports do per [Architecture and Stack](../../docs/decisions/architecture-and-stack.md). No content to speak of, which is the point. The minimum window waits for [3.0 Pitch and Camera](3.0-pitch-and-camera.md), where a view first gets wide enough for it to matter.

**Notes:**

- **Deliberately before any real content exists.** Proving the pipeline while the project is trivial means any problem you hit is a pipeline problem, not a "which of my thousand changes broke this" problem
- From here a build happens at each **phase** boundary and not otherwise. What to verify, and how to get the binary across, are in [Build Pipeline](../../ways-of-working/build-pipeline.md)
- Scaffolding, so no design doc — this exits on working
- **Working means [What to Verify on Real Hardware](../../ways-of-working/build-pipeline.md#what-to-verify-on-real-hardware), plus placeholders on a Deck with nothing sideloaded**, per [Sideloaded Art](../../ways-of-working/build-pipeline.md#sideloaded-art). Performance here is a baseline, not an exit — there's nothing to slow it down, and the target is still Build Pipeline's open question
- **Fullscreen in exports only.** The editor stays windowed, so the setting is a feature-tag override or a startup check, never the plain project setting
- **The run needs both scenes.** `input_check` for the pad end to end, the sandbox for sharpness at a scale of 3, placeholders and frame rate. An export runs only its main scene, so `input_check` went first and the sandbox is the main scene from here — it has the player from [1.1](1.1-movement-and-possession.md), which covers the pad end to end. `input_check` stays as an editor scene for re-checking a pad, per [Deck Input Parity](../../ways-of-working/deck-input-parity.md#the-dev-controller)
- **The build carries only the game.** The first preset is where [What Goes in the Build](../../ways-of-working/build-pipeline.md#what-goes-in-the-build)'s exclude filter is first set — check its Resources tab before exporting
- **This is the first pipeline run, so it answers Build Pipeline's own questions** — whether the remote debugger reaches the Deck, the SSH remote deploy option and remote-debug argument for the Godot version in use, whether the Linux VM step is worth having. What it finds goes into [Build Pipeline](../../ways-of-working/build-pipeline.md), not here
- **No Asking, Session shape, Attributes or Sprites.** Scaffolding on the *neither* route, so it exits on working, per [Exit Criteria](../README.md#exit-criteria) — with no player to read an attribute and nothing new to draw
- **No Testing.** An export preset and a fullscreen override are configuration, and a build that doesn't start fails loudly, per [What a Test Has to Earn](../../ways-of-working/automation-testing.md#what-a-test-has-to-earn). Placeholders with nothing sideloaded are already [0.2](0.2-sandbox-scene.md)'s test. The filename case check is the first CI job, per [CI](../../ways-of-working/automation-testing.md#ci), and waits with it
- **No 360 Testing.** [0.1 Input Map](0.1-input-map.md) has no tests, and the pad on the Deck is judged by hand. [0.2](0.2-sandbox-scene.md)'s fixtures and [0.3](0.3-ball-physics-test-suite.md)'s suite run in the editor from `res://`, which an export doesn't touch, and the fullscreen override applies to exports alone
